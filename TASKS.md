## Review fixes (code review of #686–#694)

- Product name in the app is 吱熊猫 (welcome label, share card, authenticator name).
- Design system: jade only on small labels, today's date and unread markers; selected states are olive; buttons at full size; no `text-2xl`; the photo radius comes from tokens; the RN Reusables Switch restyled (no shadow, motion or 1px border).
- Component sourcing: 纠错 topics use RN Reusables ToggleGroup and welcome tiles use Toggle (restyled; web gets the radio and pressed semantics native already has). The offline notice stays a page-level status pill: RN Reusables has no toast, and its Alert is an inline block.
- Shared `LoadFailed`, `NavRow` and `downloadOnWeb` replace copies across screens.
- Privacy requests keep one idempotency key per intended request until it succeeds; 今天 reads the lineage, residency and life-event lists fresh with the updates; 我的纠错 refreshes on focus; app reports are sent as `provisional`; failed read marking shows a message.
- Explanatory paragraphs removed (welcome intro, email note, relationship footnote, export description); the export status says how long it can be downloaded.

## Offline across restarts

- Done: the public API client saves successful reads of the release-wide lists and the 30 most recently opened panda and institution pages on the device (AsyncStorage, network first). A request that fails without a connection is answered from the saved copy, so an app started offline still shows them; photos come from expo-image's disk cache. e2e restarts the app with every API request failing and opens the list and the profile it loaded before (the same test fails with the cache switched off).

## Fixes along the way

- Local admin runtime and first-admin bootstrap required `API_URL` from `supabase status`, which the CLI omits since the local Data API was turned off (#671); both now fall back to the Auth gateway on port 54321.
- Session state never left "loading" when no session was stored (first-read sentinel); found by the sign-in e2e test.
- Supabase answers `otp_expired` for a wrong code as well; the app's message now covers both.
- The e2e sign-in helper accepted the code screen (which also shows the address) as signed in; it now waits for 退出登录.
- The back button on pushed screens read `canGoBack()` once at render, before an expo-router push settled on web, so screens opened from a tab showed none; `PageHeader` now subscribes to the navigation state.
- The e2e fixture recorded the birth date as `birth.date`; the public read model lists `birth_date`, so the fixture panda had no birthday until the calendar test caught it.
- expo-doctor failed on main: expo, expo-image and expo-router were behind their SDK 58 patch versions; aligned with `expo install --fix`.
- Privacy requests answered 403 `auth.aalRequired` from the app: the capability requires AAL2 and recent authentication, which email codes alone do not give. The app now uses Supabase Auth TOTP as a step-up before export and deletion, instead of weakening the policy.
- No endpoint listed a fan's privacy requests, so their status was lost after a restart; added `GET /me/privacy/requests`.
- e2e journeys seed their own panda through the API's domain modules and publish it with the release command (`e2e/global-setup.ts`); an older local database needs `npx supabase migration up --workdir infra --local` first.
