# 吱熊猫 App

The ZhiPanda iOS and Android app, built with Expo (React Native) and expo-router. It reads the
same public API as the website through `@zhipanda/api-client`.

## Run it on a phone (Windows, macOS or Linux)

1. From the repository root, install dependencies once: `npm install`.
2. Start the dev server: `npm run start -w @zhipanda/mobile`.
3. Install **Expo Go** from the App Store on the iPhone, then scan the QR code the dev server
   prints with the iPhone camera. The phone and the computer must be on the same network; if
   they are not, start with `npm run start -w @zhipanda/mobile -- --tunnel`.

No Mac or Xcode is needed for this. Code changes reload on the phone as you save.

The app talks to `https://api.zhipanda.com` by default. To point it at a local API, set
`EXPO_PUBLIC_API_BASE_URL` (for example `http://192.168.1.20:3000`) before starting.

## Styling and components

Screens are styled with Tailwind class names through [Uniwind](https://docs.uniwind.dev/)
(Tailwind 4). The design tokens live in `src/global.css`: the same Radix olive and jade steps,
radii and four text sizes as the website's design system (`docs/design/zhipanda-design-system.md`),
with a dark set. Use the token classes (`bg-background`, `text-muted-foreground`,
`border-hairline border-border`, `text-display`) rather than hex values or `StyleSheet`.

UI components come from [React Native Reusables](https://reactnativereusables.com/), the shadcn/ui
port built on RN Primitives. Its CLI copies each component's source into `src/components/ui/`,
where it is restyled to the design system:

```
npx @react-native-reusables/cli@latest add <component> --yes --styling-library uniwind
```

Run it from `apps/mobile`. `src/uniwind-types.d.ts` is generated by Metro and by
`npx uniwind generate-artifacts --css ./src/global.css --dts ./src/uniwind-types.d.ts`; keep it
committed so the typecheck knows the class names.

## Checks

- `npm run lint -w @zhipanda/mobile`
- `npm run typecheck -w @zhipanda/mobile`

Both run in CI when files under `apps/mobile/` change (`npm run verify:dev -- --scope mobile`).

## End-to-end journeys

`apps/mobile/e2e/` drives the app's web build with Playwright against the real local stack: Supabase Auth (sign-in codes are read from its Mailpit inbox) and the NestJS API on the local database, with a fresh `@example.test` user per run. Start Supabase, then run the suite; it starts the API on port 3101 and the app on port 8792 itself:

```powershell
npm run infra:start
npm run test:e2e -w @zhipanda/mobile
```

Sign-in uses Supabase Auth directly: `src/lib/supabase.ts` keeps the session in SecureStore (split into chunks under Android's size limit) and refreshes it while the app is in the foreground; `src/features/session/session.tsx` owns the signed-in state and provisions the application account once; `authedApi` in `src/lib/api.ts` adds the access token to personal API calls.

## App Store builds

Store builds are made in the cloud with EAS Build, so they also work without a Mac:
`npx eas-cli build --platform ios`. That needs an Expo account and an Apple Developer account;
EAS signs and uploads the build. The bundle identifier is `com.zhipanda.app` (see `app.json`).

Add a native dependency with `npx expo install <package>` so its version matches the Expo SDK.
