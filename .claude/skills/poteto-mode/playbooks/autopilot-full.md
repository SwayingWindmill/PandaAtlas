### Autopilot-full

Resolve the repo driver/verification surface first (`apps/mobile/.claude/skills/verify/SKILL.md` for mobile UI, `docs/agents/frontend-review.md` & `npm run smoke:web` for web UI, or `npm run verify:dev` for scoped checks).

**You own the verdicts, never the PRs. One owner carries each PR from build to merge-ready, and nothing merges until independent verifiers prove the code that lands.**

A verdict covers one patch and green CI covers one head SHA. Step 4 runs a verification swarm once at the code-ready head, and again only for a major change. The `git patch-id` rule in [`shipping.md`](shipping.md) can carry a lane's result across clean rebases, while every new head still needs green CI and a fresh independent review PASS.

1. **The operator's gates come first.** The grant covers only the queue's items; PRs outside the queue stop at merge-ready (merging any PR opened outside this conversation requires explicit user consent). On the operator's go, write the full program objective into `.audit/orchestrate/<slug>/notes.md` and restate it in your checklist so it stands across turns. Before spawning more than three owners, confirm the count if the user's request did not already specify queue size.
2. **Spawn one owner per PR, and keep its work where a replacement can find it.** Run `git`, `gh`, `node`, `npm`, `python`, and `uv` natively. Never commit or switch branches in the shared checkout `E:\Code\PandaAtlas`. Each owner runs via `invoke_subagent` (`TypeName: "self"`, `Workspace: "share"` or an isolated sibling worktree `../PandaAtlas-<task>` with its own `npm ci`, never symlinked `node_modules`) that builds, opens its PR per [`opening-a-pr.md`](opening-a-pr.md), proves the change on the real artifact, babysits to green per [`babysit.md`](babysit.md), and hands the PR off once steps 4 and 5 clear it.

   Code is ready only after [`deslop`](../../deslop/SKILL.md) and [`no-comments`](../../no-comments/SKILL.md) plus a rebase onto current `origin/main` and `npm run verify:dev -- --base origin/main`. Soon after starting, push the branch and write the decision trail in the main worktree's `.audit/orchestrate/<slug>/` per [`show-me-your-work`](../../show-me-your-work/SKILL.md) (`Workspace: "share"` does not inherit untracked `.audit/`), updating after each unit. Force-push only your own branch with `--force-with-lease` pinned to the last known remote SHA.
3. **Run owners in parallel off `origin/main`, never stacked,** unless the user requested [`autopilot-stack.md`](autopilot-stack.md), so each PR lands independently.
4. **Swarm-verify once.** Fan out independent verifiers at the code-ready head per [`swarm`](../../swarm/SKILL.md): re-run `npm run verify:dev -- --base origin/main`, prove load-bearing behavior live on the real surface (`apps/mobile/.claude/skills/verify/SKILL.md` / `npm run smoke:web` / integration suites), and obtain an independent reviewer `PASS` (own review/tests/CI do not count). Block a PR only for a concrete bug, failed domain/CI gate, or wrong shipped doc. Cap fix-forwards at two rounds per PR before escalating to the operator with exact evidence.
5. **Merge only verified heads tested on `main`.** Re-read [`merge-safety.md`](../references/merge-safety.md), never enable auto-merge (`gh pr merge --auto`), confirm `baseRefName === "main"` and independent reviewer `PASS` on the exact head SHA, wait for green `Development Verification` and `Mobile E2E`, and merge with `gh pr merge <pr> --squash --match-head-commit <verified-head>` (without `--delete-branch`). Clean up only the task's own worktree and local branch, then watch `Development Verification` on `main`.
6. **Run the root supervision tick.** Anything that loosens a gate needs independent verifier proof and explicit root approval. Arm an hourly audit tick via Antigravity `schedule` (cron/timer) when running long unattended queues. On each tick, re-read this playbook and `.audit/orchestrate/<slug>/notes.md`, inspect child progress via git branches, PRs, and logs (never just self-reports), replace stalled workers, and catch the operator up via [`ketchup`](../../ketchup/SKILL.md) only when tracked state changed.
7. **Stand down at once on operator stop.** Send every owner a zero-writes instruction and report current branch/PR state.

**Reply:** catch the operator up per [`ketchup`](../../ketchup/SKILL.md), covering each PR's state and verdict, what merged or is merge-ready, countersigns, open operator gates, and follow-ups, with links to each PR and trail.
