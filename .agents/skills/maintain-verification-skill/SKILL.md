# Maintain a verification skill

On Antigravity, read [`../poteto-mode/references/agy-tools.md`](../poteto-mode/references/agy-tools.md) before following this skill. Remember any updates under root `.agents/skills/verify/` MUST be mirrored byte-for-byte to `.claude/skills/verify/` and pass `npm run check:repository-hygiene`; the existing mobile driver skill lives at `apps/mobile/.claude/skills/verify/` (`SKILL.md` + `features/README.md`).

A feature map rots the moment the app changes. This skill is the upkeep loop for a project-local verification skill (`verify`) generated by `create-verification-skill`. Cover every feature file from source and exercise every feature live, keeping changes strictly proven.

## Outcomes

Pick one and state which:

- **clean** — every feature received source and live coverage; zero drift found. No branch or PR needed.
- **changed** — one focused PR ships proven doc, harness, or feature-map corrections.
- **blocked** — coverage could not finish or a proven fix could not ship safely; state exact blocker.

## Edit scope

Edit ONLY the verification skill's own files (`apps/mobile/.claude/skills/verify/`, or `.agents/skills/verify/` mirrored to `.claude/skills/verify/` for a root driver skill). Never edit product code inside this maintenance pass: if live behavior contradicts the map because product code regressed, report a product defect rather than softening the feature map to pass.

## Pass

0. **Locate the target.** Locate `apps/mobile/.claude/skills/verify/` (or `.agents/skills/verify/` mirrored at `.claude/skills/verify/`). If missing, stop and run `create-verification-skill` first.
1. **Index hygiene.** Read `<verify-dir>/features/README.md` and list sibling `.md` files plus `apps/mobile/tests/*.e2e.ts` (or `apps/web/tests/smoke/*.spec.ts` for web). Fix missing, extra, duplicate, or dead entries cleanly.
2. **Source wave.** Launch one parallel read-only subagent (`TypeName: "research"`, or `"self"` read-only if checking commands) per feature group. Each traces "how does this user-facing feature actually work right now from source?", flags doc/selector/route drift with `file:line` citations, and returns one concise live-verification recipe. Subagents do not drive the browser or edit files.
3. **Reconcile.** Collect every feature summary, combine overlapping recipes into efficient app journeys, spot-check cited drift, and sweep recent UI/route diffs for newly added user-facing screens missing from `features/`.
4. **Live pass.** Required even when source looks clean. The lead coordinator drives the app following `verify/SKILL.md`:
   - Hold three invariants continuously:
     1. Run `node apps/mobile/scripts/verify-doctor.mjs --mode preview` / `--mode e2e` (or the skill's Doctor check) before driving and after any unexpected failure; reset/relaunch wedged sessions rather than retrying blind.
     2. Preserve captured proof in `.audit/verify/` (or the skill's artifact dir) across every cleanup step and confirm artifacts exist after teardown.
     3. Clean up every process/scratch residue launched by the run when done.
   - Doctor failures caused by skill drift are fixed under edit scope and re-run once before marking `blocked`. Features gated by external prerequisites (or Windows Hyper-V ports requiring `Mobile E2E` on CI) become `verified-unreachable` only with the exact prerequisite and route attempted (update `Gotchas` if the map omitted that prerequisite).
5. **Triage.** Wrong route/selector/user-POV description -> fix doc drift. Harness helper fails on working app -> fix harness under `verify` rules and re-drive live. Broken product behavior -> log as product bug, do not edit app code here.
6. **Verify & ship.** If modifying root `.agents/skills/verify/`, mirror `.agents/skills/verify/` <-> `.claude/skills/verify/` cleanly. Run `npm run verify:dev -- --base origin/main` (including `check:repository-hygiene` and `check:doc-references`), open one clean PR if **changed**, and store temporary run notes strictly in `.audit/` (uncommitted).
