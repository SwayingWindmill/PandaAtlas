# 科普文稿说明

给撰稿人。按本文改 `data/curation/learning/learning.json`。不用读程序。下面列出现在文件里的每一格。

现在每一条都是 `draft`。正式版的 App 和 `GET /api/v2/learning` 只返回 `published`，所以读者看到「科普还在写」。开发版会预览文件里的草稿，方便审阅。草稿可以不带 `[草稿]` / `[draft]` 标记；维护者审过、同意给读者看的条目才改成 `published`。

## 改哪一份文件

只改这一个文件：

`data/curation/learning/learning.json`

不要改 `infra/supabase/migrations/` 里的 SQL。文件改完后，由维护者运行：

`python scripts/curation/build_learning_content_migration.py --write`

那条命令会生成新的数据库迁移。迁移进生产之后，状态为 `published` 的条目才会出现在正式版里。

`version` 由维护者在发布时改成当天的版本号，形如 `2026.10.29.1`。撰稿人不用改它。

## 草稿和发布

每条都有 `status`：

| 值 | 含义 |
|---|---|
| `draft` | 草稿。可以先写成正式句子，不必加 `[草稿]`。`url` 可以先空着（`null`），也可以先写上 `https` 来源和 `citedOn`。读者在正式版里看不到。 |
| `published` | 可以给读者看。句子里不能再有 `[草稿]` 或 `[draft]`。每条至少有一条来源：`url` 是 `https://` 开头的地址，`citedOn` 是核对那一页的日期，写成 `2026-10-29`。 |

不要把没有来源的句子标成 `published`。

## 语气

- 写给熊猫爱好者。好懂，不口语，不造词。
- 一句一事。按钮和条目标题短，正文把一件事说完。
- 只写来源里有的内容。来源没说的，不要补。
- 认脸只写照片上能核对的特征，不写性格、轶事和「据说」。
- 英文是同一段意思，不是另写一篇。
- 不用「这里展示的是」「我们只收录」这类说明。

## 来源

每条的 `sources` 至少留一项。

| 字段 | 怎么填 |
|---|---|
| `title.zh` / `title.en` | 来源的名字。发布后不能带草稿标记。 |
| `url` | `https://` 开头的具体页面。草稿可以暂时写成 `null`，但要和 `citedOn` 一起空着或一起写上。 |
| `citedOn` | 你核对那一页的日期，`2026-10-29`。 |

来源可以是基地、动物园或主管部门的页面，或一本写明页码的书。书没有网址时，发布前先跟维护者确认怎么写 `url`（不要发明一个链接）。

## 字数

按字符数算，含标点。认脸提示的正文可以是空字符串。超出就缩短，不要靠程序截断。

| 字段 | 中文最多 | 英文最多 |
|---|---:|---:|
| 条目标题 `title`、小节标题 `heading` | 24 | 48 |
| 名词 `term`、认脸小标题 `label` | 16 | 40 |
| 知识卡摘要 `summary` | 80 | 160 |
| 专题摘要 `summary` | 120 | 240 |
| 知识卡正文 `body`、专题小节正文 `body` | 400 | 800 |
| 名词释义 `definition`、认脸提示 `body`、挑战提示 `tip` | 200 | 400 |
| 挑战题目 `prompt` | 40 | 80 |
| 来源名称 `title` | 40 | 80 |

中英都要写。每个文字字段都是 `{ "zh": "…", "en": "…" }`。

`slug` 是网址里的短名，小写字母、数字和连字符。已经有的 `slug` 不要改，否则已经打开过的链接会断。新条目自己起一个不重复的 `slug`。

## 照片和熊猫

认脸指南和认脸挑战不上传照片。它们用 `pandaSlug` 指向已经在名录里的熊猫。指南用封面。挑战的选项也用封面；答案若还有另一张已发布的照片，大图用那一张，避免和大图、正确选项是同一张。

熊猫的短名必须是 `data/curation/pandas/pandas.csv` 第一列里已有的，例如 `bao-li`、`lun-lun`。不要新造一只熊猫。名录里没有的，先不要写进这一份文件。

挑战固定四选一：`answerPandaSlug` 是答案，`decoyPandaSlugs` 正好三只，三只互不相同，也不能和答案相同。

## 现在文件里的每一格

每条的 `status` 都是 `draft`。格子的名字就是文件里的字段名。改句子时中英文一起改。

### 认脸指南 `faceGuides`

每条是一只熊猫。`pandaSlug` 已填好，不要改成名录里没有的短名。`title` 是读者看到的名字。四个提示的 `key` 和顺序不要动：`shape`、`leftRight`、`eyePatches`、`ears`。`shape` 的中文小标题写「脸型」，不要写「形状」。`body` 可以先留空字符串 `""`：空的提示不会出现在页面上。有字的提示才会显示。

**`bao-li`**（熊猫 `bao-li`），标题「宝力」。来源是史密森尼国家动物园的区分说明。

| key | 现在的小标题 | 现在的提示 |
|---|---|---|
| `shape` | 脸型 | 两颊不如青宝蓬松。 |
| `leftRight` | 左右差别 | （空，页面不显示） |
| `eyePatches` | 黑眼圈 | 眼斑较宽，尖端比青宝的更向外翘。 |
| `ears` | 耳朵 | （空，页面不显示） |

**`lun-lun`**（熊猫 `lun-lun`），标题「伦伦」。只有 `shape`（脸型）写了「两颊圆润蓬松。」其余三格的 `body` 是空的，页面不显示。

脸型写在 `shape`，左右是否对称写在 `leftRight`。有字的句子都要能在你注明的页面上核对。

### 认脸挑战 `challenges`

每题填 `prompt`（题目）、`tip`（认对或认错之后给读者的一句提示）和来源。答案和三个干扰项用熊猫短名。四个选项都用各自已经发布的封面，答题前不写名字。

`prompt` 只在答案那只熊猫还有第二张已发布照片时出现：大图用那张不同的照片，选项仍用封面，并写上名字。只有一张照片时，不放大图，题目改成「哪一只是{它的名字}？」，名字等选完才出现在照片下面。提示文字不变。

| slug | 答案 | 三个干扰项 | 文件里的 `prompt` | 只有一张照片时屏幕上的题目 | 提示在说 |
|---|---|---|---|---|---|
| `bao-li-round` | `bao-li` | `lun-lun`、`lei-lei`、`yang-yang` | 看照片，选出这只熊猫 | 哪一只是宝力？ | 宝力的眼斑和脸颊 |
| `lun-lun-round` | `lun-lun` | `bao-li`、`ya-lun`、`yang-yang` | 看照片，选出这只熊猫 | 哪一只是伦伦？ | 伦伦的脸颊，以及洋洋的耳朵 |

提示要写看照片才能用上的特征，并和来源对得上。

### 比一比要用的内容

比一比把两只熊猫并排放，「区分要点」只转述上面两种条目里已经写好的句子，不另写：

- 两只各自的认脸指南（`faceGuides`）里有字的提示，按脸型、左右差别、黑眼圈、耳朵四格对齐。只有一边写了的格子，另一边显示「还没写」。
- 一只是答案、另一只在选项里的认脸挑战（`challenges`）的 `tip`。
- 这些条目的来源，列在页面最后。

一条都没有时，页面显示「区分要点还在整理」，并按熊猫列出还空着的格子。正式版只读 `published` 条目，所以现在正式版上每一对都是这个状态。

比一比会从熊猫页和猜错的题目里打开。最常被打开的是同住一个地方的熊猫（猜熊猫从同一个地方挑干扰项），以及同一道挑战里的熊猫。按这个顺序补最有用：

1. 审过 `bao-li`、`lun-lun` 两份认脸指南和两道挑战之后改为 `published`。
2. 补齐这两份指南的空格：宝力的左右差别、耳朵；伦伦的左右差别、黑眼圈、耳朵。
3. 给挑战里的干扰项 `lei-lei`、`yang-yang`、`ya-lun` 各写一份认脸指南。
4. 同一个地方住着好几只熊猫的，挑常被放在一起的几只先写。

每一格都要能在注明的页面上核对；找不到出处的格子留空，不要用「长得像」之类的话补。

## 交稿

1. 只改 `data/curation/learning/learning.json`。
2. 审阅阶段：`status` 保持 `draft`。句子可以不带 `[草稿]`。空的认脸提示保持 `""`。
3. 维护者审过、同意给读者看的条目：`status` 改为 `published`，去掉任何 `[草稿]` / `[draft]`，并写上 `https` 来源和 `citedOn`。
4. 把文件交给维护者。维护者运行上面的命令并发布迁移。不要自己改 SQL。

要加新的知识卡、专题、名词、认脸指南或挑战，复制文件里同一种条目，换一个新的 `slug`，字段和上面相同。认脸仍只能指向名录里已有的熊猫。

## 文章 `articles`

科普首页读的是文章，不是知识卡。完整篇幅以后写进 `articles`。字段、块的种类和一篇例子见 `data/curation/learning/ARTICLE_SCHEMA.md`。现在的三篇是从上面的知识卡和专题拆出来的草稿，句子没有另写。知识卡和专题先留在文件里，正式的长文落到文章上。
