# IAM-06 — staff identity and access lifecycle acceptance

Ticket: [#430](https://github.com/SwayingWindmill/PandaAtlas/issues/430); parent map: [#424](https://github.com/SwayingWindmill/PandaAtlas/issues/424). This record covers IAM-01 through IAM-05 without changing production roles or generating a second IAM system.

## Evidence boundaries

1. **Live operator/browser acceptance**: the owner verified Supabase email sign-in and TOTP AAL2, reviewer invitation through the Chinese console and Mailpit, acceptance from a distinct browser profile, Review accessibility without Publication/Identity privileges, role grant and revoke, and staff suspension/reinstatement (recorded in #432–#434). The original owner's reviewer remained active with an accepted invitation, but a later audit read did **not** find corresponding staff-owned state/audit/Outbox records. That original historical discrepancy remains unexplained and is not claimed as verified.
2. **Real NestJS/PostgreSQL seam** (`services/api/test/integration/identity-http.integration.spec.ts`): a scoped reviewer invitation remains unprivileged before email verification and activation; an independent `member` contributes a Panda correction; the invited reviewer accepts and *claims* the Review case, while Publication remains forbidden. The manager grants and revokes `audit_reader` with reasons, and unchanged reviewer JWT observes permissions appear/disappear on the next request. The manager suspends and reinstates the reviewer; same valid JWT is denied during suspension and regains only non-revoked Review rights afterward. Stale AAL2 can read staff details but cannot mutate. State events, authorization audits and Outbox share the exact correlation IDs for each transition.
3. **Committed evidence**: in GitHub's disposable Supabase only, `IAM06_COMMIT_EVIDENCE=1` runs that same HTTP lifecycle after the normal integration suite, **commits** it, then queries from a separate PostgreSQL connection. It asserts two durable account state events, matching authorization audit and Outbox facts, a Review case assigned to the reviewer, and the final account state `active`. The command prints a single `IAM-06 committed evidence` line if all assertions pass. Local developer DBs always use a rollback-only transaction. The synthetic signer/JWKS and test sessions prove authorization and persistence, not real email delivery or browser TOTP. The independent local browser exercise below supplies that additional evidence.
4. **Independently exercised actual local browser/Auth path (2026-10-08)**: with user authorization, a separate local QA administrator and reviewer were created (neither is an existing staff account). Microsoft Edge automated the **real** Chinese login form using local Mailpit email codes, real Supabase TOTP enrollment and AAL2 verification, staff invitation and acceptance, and actual staff stop/restart buttons without intercepting/mocking any BFF/API route. The reviewer used a separate unmodified browser session throughout. The Review BFF returned **HTTP 200 → 403 → 200** before suspension, while suspended, and after reinstatement. Marker `iam06-acceptance-ac876445`; reasons `IAM06-acceptance-suspend-iam06-acceptance-ac876445` and `IAM06-acceptance-reinstate-iam06-acceptance-ac876445`. An independent PostgreSQL client confirmed **two** `identity.account_state_events`, **two** matching `identity.authorization_audit_events`, **two** matching `integration.outbox_events`, two matching correlation IDs with the same test manager actor, and final reviewer state `active`. After checking those durable facts, all temporary QA administrator grants and the QA reviewer's Reviewer grant were explicitly revoked; cleanup is append-only with audit/Outbox, and a follow-up database query found **zero active QA administrators and zero active QA reviewers**. Historical evidence remains intact. The original human-run missing records are not retrospectively explained by this fresh successful run.
5. **Production administration**: [IAM-05 PR #435](https://github.com/SwayingWindmill/PandaAtlas/pull/435) CI executed both positive first-admin and signed recovery cases on an empty disposable Supabase. Local bootstrap documentation and [production operator procedure](../runbooks/production-first-administrator.md) cover separate trusted environments. **No real production bootstrap/recovery has been authorized or executed.**

## Decision and follow-ups

- Preserve the verified four-eyes invariant: the case contributor and reviewer are **different Supabase subjects**; Review refuses a reviewer claiming their own submission.
- Preserve the `identity.staff.read` split: staff GETs require authorized live session, not recent AAL2; real authority mutations still require AAL2, recent authentication, and valid session.
- Preserve out-of-scope public UI failures in [#436](https://github.com/SwayingWindmill/PandaAtlas/issues/436) rather than changing profile/map implementations as part of IAM.
- Do not claim historical staff audit evidence exists for the owner's original manual actions when it does not. Both fresh disposable-CI committed evidence **and** a separate unmocked local-browser IAM lifecycle establish the current implementation's persistence path, while the historical discrepancy is still unexplained. Neither is production evidence.
