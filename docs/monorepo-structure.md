# Panda Atlas Monorepo Draft (Historical Scaffold)

- Document status: **Historical scaffold reference**
- Current architecture decisions: [`docs/architecture/README.md`](architecture/README.md)
- Current deployment status: [`docs/deployment/runtime-status.md`](deployment/runtime-status.md)

This document records the repository shape proposed during the initial scaffold. It is not the current deployment plan and must not be used to introduce a container-hosted production API. ADR 0002 supersedes its deployment assumptions while the repository layout examples remain useful historical context.

The current enforced layout is defined by [`contracts/repository-structure.v1.json`](../contracts/repository-structure.v1.json). The active npm workspaces are `apps/web` and `services/worker-api`; the illustrative `packages/` section below was never activated and is not an available workspace.

## Scope

- Frontend: Next.js (App Router), Tailwind CSS v4, shadcn/ui, map rendering.
- Backend: FastAPI, SQLAlchemy, Alembic, Pydantic.
- Data platform: Supabase Postgres + PostGIS + Auth + Storage.
- Historical deployment proposal: `web` on Vercel, `api` on a container host, database on Supabase. The accepted target now uses bounded Vercel API functions and no persistent self-managed production server.

## Runtime Boundaries

- `apps/web` only talks to `services/api` over HTTP.
- `services/api` is the only write path to Postgres and Storage metadata.
- Supabase Auth JWT is verified in FastAPI for admin routes.
- Supabase Storage signed URLs are generated by backend for controlled media access.

These authority boundaries remain relevant, but the concrete deployment runtimes are governed by ADR 0002 and the deployment runtime status page.

## Historical Build and CI Proposal

1. Lint/typecheck:
   - `npm run lint:web && npm run typecheck:web`
   - `uv run ruff check . && uv run pytest -q`
2. Schema checks:
   - Run Alembic migration check in CI before deploy.
3. Contract checks:
   - Keep `services/api/openapi/panda-atlas-v1.yaml` synced from FastAPI docs.
4. Original deploy assumption:
   - Merge to `main` triggers Vercel for frontend and a container deploy for backend.

The fourth item is superseded. Current development and release commands are documented in [`docs/development-operations.md`](development-operations.md), and managed deployment phases are documented under `docs/deployment/`.
