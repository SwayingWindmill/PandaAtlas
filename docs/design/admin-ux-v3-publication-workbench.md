# Admin UX V3 — Publication release-control workbench (#459)

## Purpose

This is a scoped **Impeccable Operate** and Kiranism-direction improvement in the existing PandaAtlas Admin preview, stacked on Curation PR #458. The previous Publication UI put a tall current-release card, full-width version table and a separate stack of inspection/count/diff/history/action cards onto one long vertical page. The result forced staff to scroll between the candidate list, comparison and actual version action. It could be fully functional without being an efficient operator workflow.

## Updated interaction

- The current public version is a concise top status strip with its real version, build time, suspended state and inspect action, rather than a hero KPI card. Pending data is explicitly loading; absent published data is not invented.
- The left **版本队列** contains the existing typed TanStack table and nuqs lifecycle filter and pagination. Selecting a version remains reflected in `release` URL state; `aria-pressed` communicates which record is selected. The low-frequency candidate builder stays in an optional disclosure, visible only with the existing management capability.
- The right **所选版本检查** keeps the selected version, real resource counts, diff against the current version, blockers/limitations and the next authorized action in one task flow. Counts are a compact factual summary, and diff records are readable rows rather than more cards. The lifecycle history is secondary after the decision/actions. Raw release IDs and actor IDs remain disclosed for technical traceability.
- Authentication and mutation errors, their re-login/MFA recovery links, and success notifications appear in the selected-version pane rather than at the bottom of the overall page. The success `role=status` exists before its text changes; the pre-existing AlertDialog still confirms publication, rollback and emergency actions with version and reason. Rollback and suspension now use outlined danger treatment instead of being visually equivalent to the primary activate action.
- The server's lifecycle eligibility, capabilities, typed release commands, client cache invalidation and reauthentication policies are unchanged. UI never fabricates amounts, comparison entries or approvals.
- The old warning `This is the current public release.` now reads as a specific current-release note rather than a claim that *every* action on that version is forbidden (emergency suspension can still be permitted).
