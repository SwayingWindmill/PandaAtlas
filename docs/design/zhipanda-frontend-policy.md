# 吱熊猫 ZhiPanda 前端设计政策

- **状态：** 当前生效的前端品牌、视觉与交付政策
- **生效日期：** 2026-07-25
- **适用范围：** `apps/web` 的公开页面、共享组件、视觉样式、文案与前端测试
- **取代：** 本文件在品牌定位和视觉方向上取代 `frontend-design-principles-and-standards.md` 中的“PandaAtlas / 自然史档案馆”定义
- **品牌与文案合同：** `zhipanda-public-brand-and-copy-contract.md` 定义公开命名边界、双语语气和旧品牌引用清单

## 1. 项目定义

中文品牌名为 **吱熊猫**，英文品牌名为 **ZhiPanda**。

吱熊猫是一个主要面向熊猫爱好者的现代熊猫信息网站。用户应当能够从真实熊猫图片和名字开始，快速了解个体资料、家庭关系、生活地点、时间线与公开来源，并自然地继续探索其他熊猫。

产品首先是一套亲近、现代、图片驱动的公众体验；可信数据、来源、许可和修订能力是它的基础，而不是压过熊猫内容的视觉主题。

## 2. 外部设计规则锁定

本项目参考以下两个上游项目，但不在构建或运行时自动跟随上游变化。选中的规则已经固化在本文件中；任何升级必须通过独立 PR，重新完成视觉、无障碍和浏览器回归。

### Taste Skill

- 仓库：https://github.com/Leonxlnx/taste-skill
- 使用范围：`design-taste-frontend` 的 brief inference、VARIANCE / MOTION / DENSITY、redesign audit 与 anti-slop 原则
- 固定快照：2026-07-25 审阅的 `main` 规则投影
- 注意：上游 v2 仍处于实验演进状态，因此本项目只采用本文明确列出的规则，不自动更新

Taste Skill 在吱熊猫中负责：首页、个体页首屏和图片构图的品牌辨识度；避免通用 SaaS Hero、装饰性大渐变和模板化卡片矩阵；为不同页面分别设置视觉变异度、动效强度和信息密度；改造现有页面时保留路由、内容语义、可访问性和核心任务。

### Impeccable

- 仓库：https://github.com/pbakaus/impeccable
- 固定版本：`cli-v2.3.2`
- 固定提交：`b913668`
- 使用范围：设计上下文、critique、audit、distill、harden、polish 和确定性反模式检查

Impeccable 在吱熊猫中负责：全站组件、Token、排版和交互状态一致性；响应式、无障碍、性能、空错状态与双语压力测试；清理嵌套卡片、低对比文字、默认渐变和通用图标方块；在交付前执行 critique、audit、harden 与 polish 检查。

## 3. 规则优先级

发生冲突时，按以下顺序处理：

1. 真实性与媒体许可、隐私、安全和领域事实；
2. 无障碍与核心任务可完成性；
3. 本文件定义的吱熊猫产品与视觉规则；
4. Impeccable 的工程和质量规则；
5. Taste Skill 的艺术指导规则；
6. 仍与前述规则一致的旧项目约定。

不得为了视觉完整度使用其他熊猫图片、AI 生成个体照片、随机图片服务或来源不明媒体。

## 4. 视觉方向

整体方向为：

> 真实熊猫影像、现代信息结构、轻量自然色彩。

必须做到：

- 明亮、温暖、清爽的浅色背景；
- 现代无衬线字体和清楚的中英文层级；
- 低饱和绿色作为主品牌色，暖色只作辅助；
- 图片是首页和个体熊猫页面的主要视觉锚点；
- 适度圆角，阴影只用于真正需要抬升的层级；
- 数据列表优先使用分隔线、定义列表和清楚的行列结构；
- 动效短促并解释状态或空间关系，完整支持 `prefers-reduced-motion`。

不得默认使用：通用 SaaS Dashboard 构图；居中巨型 Hero 加多按钮组合；大面积营销渐变、玻璃拟态或持续装饰动画；卡片套卡片；每个标题上方都放圆角图标方块；卡通竹叶、脚印和幼儿化熊猫元素；随机占位图片服务，例如 Picsum、Placehold 或任意未审核图片源。

## 5. 页面设计旋钮

| 页面 | VARIANCE | MOTION | DENSITY |
|---|---:|---:|---:|
| 首页 | 6 | 2 | 4 |
| 个体熊猫首屏 | 5 | 2 | 6 |
| 个体熊猫正文 | 3 | 2 | 7 |
| 熊猫检索 | 3 | 2 | 8 |
| 谱系 | 3 | 3 | 7 |
| 地图 | 3 | 3 | 7 |
| 机构、地点、我的熊猫 | 4 | 2 | 6 |

首页允许更明显的编辑构图；检索、谱系和地图不得为了视觉变异降低扫描效率。

## 6. 图片规则

### 首页

- 首屏采用“搜索与价值说明 + 一张授权熊猫主图”的非对称双栏布局；
- 主图必须链接到具体熊猫档案；
- 图片附近显示真实署名、许可和原始来源；
- 搜索入口在首屏内保持明确，不得被图片推到下一屏。

### 个体熊猫

- 有授权媒体时，选择 `primary` 媒体作为首屏视觉中心；
- 桌面采用图片与身份资料双栏，移动端采用上图下信息；
- 图片不承载大段覆盖文字，不叠放装饰性状态徽章；
- 页面下方媒体区可以继续展示完整图库和许可记录。

### 无图或加载失败

- 保留与主图相同的稳定布局；
- 明确说明无授权图片或图片加载失败；
- 不使用其他熊猫或通用图片替代；
- 文字档案、关系、地点和来源仍须完整可用。

## 7. 文案规则

公开文案优先使用熊猫爱好者能直接理解的语言，例如“熊猫”“资料”“家庭关系”“生活过的地方”“最近更新”。技术性版本、投影和交付术语放在来源或方法区域；不把推测写成熊猫性格；不过度卖萌，不用行政数据库语气。

## 8. 每个前端 PR 的完成条件

1. 对照本文件完成设计自检；
2. 运行 `npm run check:design-policy -w apps/web`；
3. 运行架构检查、lint 和 typecheck；
4. UI 可见变更提供中英文桌面与移动截图；
5. 验证键盘、焦点、减少动画、无 JavaScript 核心路径；
6. 验证有图、无图、加载失败、部分数据和长文本状态；
7. 不修改或覆盖并行的数据采集工作。
