# 吱熊猫：熊猫爱好者体验方向与首页原型

> 状态：Prototype input / 尚未成为正式设计政策
>
> 原型问题：哪一种首页结构最能同时体现 **A 的视觉品质、B 的用户关系、C 的探索体验**？
>
> 原型形式：同一路由下的四个高保真变体，通过 `?variant=A|B|C|D` 和底部切换器比较。

## 1. 方向摘要

吱熊猫的公开体验从“以档案和证据追溯为第一印象”调整为“以熊猫爱好者的发现、关注和持续探索为第一价值”。

目标体验是：

> **一个明亮自然、精致活泼的熊猫生活网站。用户从喜欢的一只熊猫开始，认识它的家族、生活地点和最近动态，并逐渐形成自己的熊猫世界。**

这次方向不取消真实性、来源、资料状态和修订能力，而是重新安排它们的公开层级：

1. 第一层展示熊猫、照片、关系、生活经历和动态；
2. 第二层用简洁语言提示资料范围、不确定性和最近核实；
3. 第三层提供来源、详细状态、版本和修订信息。

公开页面不再把“追溯证据”作为品牌主张、首屏卖点或主要视觉语言。

## 2. 产品承诺

吱熊猫帮助熊猫爱好者：

- 快速找到并认识一只熊猫；
- 关注喜欢的熊猫，并持续看到值得关注的更新；
- 沿家族、机构、地点、年龄和生活经历发现更多熊猫；
- 浏览真实、优质、许可明确的照片和视频；
- 保存、分享和整理自己的熊猫兴趣；
- 在信息不完整或存在争议时，获得清楚但不压迫主体验的说明。

核心品牌价值不是“我们拥有一套档案系统”，而是：

> **让每一只熊猫更容易被认识，让每一次喜欢都有继续探索的方向。**

## 3. 主要受众

### 3.1 第一受众：熊猫爱好者

他们通常会：

- 记得熊猫名字、昵称、生日和亲属；
- 关注某只熊猫、某个家族或某家机构；
- 对照片、成长、迁居、生日和家庭关系感兴趣；
- 从社交平台、新闻、直播或搜索引擎进入；
- 愿意重复访问，而不仅是一次性查资料。

### 3.2 第二受众：轻度兴趣公众

他们可能只认识一两只熊猫，需要通过漂亮、直观的页面快速获得兴趣和方向。

### 3.3 第三受众：教育与研究型访客

他们需要更完整的资料、来源和结构化路径，但这些能力不应决定所有公开页面的第一印象。

## 4. 体验模型：A + B + C

### A — 视觉品质：熊猫生活杂志

承担品牌第一印象和内容品质：

- 优质熊猫摄影是主要视觉资产；
- 大图、非对称编辑网格和大小变化形成节奏；
- 页面像现代自然与动物杂志，而不是数据库；
- 标题简洁、有邀请感；
- 每个内容单元都提供继续探索的下一步。

### B — 用户关系：关注与陪伴

承担重复访问和个人关系：

- 关注一只熊猫；
- 查看关注熊猫的更新；
- 收藏照片、动态、家族或主题；
- 建立“我的熊猫”清单；
- 获得生日、重要事件和新内容提醒；
- 从一条动态返回熊猫资料、家族和地点。

### C — 探索体验：从一只熊猫继续走

承担产品差异化：

- 从当前熊猫进入父母、子女、兄弟姐妹；
- 查看生活过的地点和关联机构；
- 发现同年出生、同机构、同家族或相似经历的熊猫；
- 保留当前焦点和探索路径；
- 地图与关系可视化始终提供普通列表等价路径。

## 5. 设计性格

网站应当呈现：

- **漂亮：** 有明确的视觉构图、摄影选择和排版品质；
- **活泼：** 页面有节奏、动作和邀请感，但不喧闹；
- **亲近：** 文案从熊猫和用户兴趣出发；
- **好奇：** 每个页面都鼓励发现下一只熊猫；
- **精致：** 细节统一，不像模板化社区或通用后台；
- **不幼稚：** 不使用宝宝语、吉祥物旁白或廉价卡通符号；
- **真实：** 不虚构性格、情绪、故事、地点和关系。

建议的内部设计标签：

> **Playful Nature Editorial / 明亮自然的熊猫生活杂志**

## 6. 信息优先级

### 6.1 首页

首页首先回答：

1. 今天有什么熊猫值得看看？
2. 我能从哪里开始认识一只熊猫？
3. 我关注的熊猫有没有新内容？
4. 我还能沿什么关系或主题继续探索？

不应首先展示：

- 版本号；
- 发布机制；
- 审核流程；
- 数据覆盖指标；
- 来源数量；
- “可信档案”类品牌口号。

### 6.2 熊猫资料页

首屏优先：

- 名字和常用别名；
- 一张代表性真实照片；
- 出生信息、性别、当前或最近确认的生活地点；
- 一句话身份介绍；
- 关注按钮；
- 最近动态；
- 家族和生活足迹入口。

资料状态与来源进入次级区域，不与身份信息争夺首屏。

### 6.3 动态页

动态不是通用社交信息流，而是由公开熊猫事实、机构内容和经过整理的媒体组成的熊猫更新流。

每条动态应回答：

- 哪只熊猫；
- 发生了什么；
- 什么时候；
- 可以继续去哪里看。

### 6.4 家族页

家族页以“认识这一家”为主，而不是先展示复杂关系图。

优先提供：

- 家族代表成员；
- 代际故事；
- 当前焦点熊猫；
- 亲属卡片；
- 结构化家族列表；
- 可选关系图。

### 6.5 地点与机构页

重点展示：

- 这里有哪些熊猫；
- 哪些熊猫曾经生活在这里；
- 最近有哪些相关动态；
- 可以沿哪些熊猫继续探索。

## 7. 视觉系统方向

### 7.1 色彩

从单一克制的档案绿色扩展为受控的自然色组：

- **竹叶绿：** 主品牌、主要按钮、关注状态；
- **嫩芽绿：** 柔和背景、筛选和辅助交互；
- **日光黄：** 精选、生日、积极提醒；
- **天空蓝：** 地点、旅居和地图内容；
- **柔和橙：** 动态、生活事件和编辑强调；
- **暖白 / 奶油白：** 页面主背景；
- **深墨色：** 正文和高对比区域。

颜色必须由统一语义管理，不能每个功能自行创造配色。

### 7.2 摄影

- 使用真实、许可明确的熊猫照片；
- 优先选择近景、动作、环境和关系感强的照片；
- 允许横幅、竖图和方形裁切形成编辑节奏；
- 不使用生成式熊猫纪录照片；
- 不用另一只熊猫的照片替代无图个体；
- 署名和许可清楚存在，但不压过主要内容。

### 7.3 排版

- 正文、导航、资料和交互以高可读无衬线为主；
- 编辑标题可使用更有性格的衬线或展示字体；
- 标题尺度有明显层级，但不以超大标题挤压首屏内容；
- 中文和英文分别保证自然的行长、换行和节奏；
- 数字、日期和熊猫名字需要快速扫描。

### 7.4 形状

- 主要内容区域使用中等圆角；
- 照片可以有较柔和的裁切；
- 熊猫头像可以使用圆形或有机边界；
- 状态、标签和筛选才使用药丸形；
- 避免整页都是相同白色卡片；
- 允许少量贴纸式强调，但不进入儿童手账风。

### 7.5 动效

允许：

- 图片与内容轻微进入；
- 卡片悬停层次；
- 关注状态反馈；
- 家族焦点切换；
- 地图和地点卡同步；
- 动态筛选和展开。

禁止：

- 满屏视差；
- 漂浮竹叶；
- 自动播放的装饰动画；
- 阻碍阅读的弹跳或旋转；
- 仅为“活泼”增加的持续运动。

## 8. 文案方向

公开语气：

- 直接；
- 亲切；
- 有邀请感；
- 简洁；
- 不幼稚；
- 不夸张。

推荐表达：

- “认识它”
- “看看这个家族”
- “继续发现”
- “关注这只熊猫”
- “最近动态”
- “生活过的地方”
- “和它有关的熊猫”
- “今天认识谁？”

避免在主界面使用：

- “证据链”
- “结构化结论”
- “发布投影”
- “Schema”
- “交付状态”
- “不可变发布”
- “审计记录”

上述技术概念只在数据、方法或管理场景使用。

## 9. 真实性的公开层级

不强调证据，不等于隐藏重要限制。

### 第一层：自然语言内容

例如：

- “目前生活在……”
- “最近公开记录显示……”
- “已知父母为……”
- “部分生活经历仍待补充。”

### 第二层：简洁资料提示

例如：

- 最近核实日期；
- 部分资料可用；
- 关系存在不同记录；
- 当前地点并非实时位置。

### 第三层：详细资料区

包括：

- 来源；
- 许可；
- 详细状态；
- 修订；
- 数据下载；
- 版本信息。

## 10. 核心用户旅程

### 10.1 从名字进入

搜索熊猫名字 → 查看资料首屏 → 关注 → 查看最近动态 → 进入家族或地点。

### 10.2 从社交分享进入

打开某条熊猫动态 → 认识该熊猫 → 查看相关照片或家族 → 关注。

### 10.3 从首页闲逛

查看今日精选 → 打开一只熊猫 → 沿家族成员继续 → 保存一个主题或关注对象。

### 10.4 回访

进入“我的熊猫” → 查看关注更新 → 打开一条事件 → 继续探索相关熊猫。

### 10.5 从地点进入

打开机构或地点 → 查看当前与历史熊猫 → 选择一只 → 进入资料和关系网络。

## 11. 关注关系设计

关注对象至少包括：

- 熊猫；
- 后续可评估家族、机构和主题。

关注后提供：

- 关注状态；
- 关注列表；
- 动态聚合；
- 生日和重要事件提醒；
- 新照片、新资料和地点变化提醒；
- 通知偏好控制。

不采用：

- 关注数量竞争；
- 粉丝排行榜；
- 无意义连续签到；
- 用游戏化数字替代真实内容；
- 未经审核的即时动态。

## 12. 探索模型

每个熊猫页面至少提供三类下一步：

1. **关系：** 父母、子女、兄弟姐妹和家族；
2. **空间：** 当前或曾生活地点、机构和同地熊猫；
3. **主题：** 同年出生、相似经历、近期热门或编辑合集。

探索应满足：

- 当前熊猫始终清楚；
- 点击后不会丢失上下文；
- URL 可保存当前焦点；
- 移动端不依赖大画布；
- 图形旁有结构化列表；
- 不要求用户先学习图谱操作。

## 13. 首页建议结构

推荐首页由以下模块组成：

1. 品牌导航与全局搜索；
2. 今日或本周主角；
3. 我关注的熊猫 / 登录前的关注价值说明；
4. 最近熊猫动态；
5. 家族故事或关系探索；
6. 地点与机构探索；
7. 精选照片和视频；
8. 随机发现；
9. 次级数据与方法入口。

模块顺序可根据登录状态调整，但首页不能变成纯个性化 Dashboard，也不能退化为内容门户。

## 14. 响应式原则

### 移动端

- 首屏在照片、名字、主 CTA 和搜索之间保持清楚优先级；
- 关注、分享和继续探索可触达；
- 横向内容带应可滚动且有可见提示；
- 家族和地图提供卡片式替代；
- 重要内容不依赖悬停。

### 桌面端

- 使用非对称编辑布局；
- 同时展示内容和探索线索；
- 可提高照片尺寸和信息密度；
- 不把移动端必要信息变成桌面专属。

## 15. 无障碍与性能

- 保持 WCAG 2.2 AA；
- 状态不只依赖颜色；
- 动效尊重 `prefers-reduced-motion`；
- 所有照片有合适替代文本；
- 键盘可完成关注、切换和探索；
- 首屏只加载必要主图；
- 后续媒体延迟加载；
- 地图、图谱和视频不是首屏阻塞资源；
- 无 JavaScript 时仍能查看核心内容和关系链接。

## 16. 原型结构

原型使用四个结构明显不同的首页变体：

### Variant A — 生活杂志

主要验证：

- 大图和编辑布局能否建立理想的品牌品质；
- 关注和探索是否能自然嵌入内容，而不是变成工具条；
- 首页是否足够漂亮，同时仍能快速找到熊猫。

### Variant B — 关注客厅

主要验证：

- 关注关系是否足以成为首页核心；
- 动态、生日和回访内容是否清楚；
- 个性化体验是否会过度接近通用社交产品。

### Variant C — 探索地图

主要验证：

- 家族、地点和主题是否能形成独特的发现体验；
- 用户能否从一个焦点熊猫自然继续；
- 探索视觉是否会增加认知负担。

### Variant D — 潮流品牌叙事

参考 LINE FRIENDS About 页的品牌大片式节奏进行转译，不复制其角色、Logo、文案或媒体资产。

主要验证：

- 全幅摄影、超大标题和黑白章节切换能否显著提升品牌记忆；
- 长页叙事能否把熊猫、家族、地点和关注关系组织成连续故事；
- 高饱和功能色块能否让网站更年轻、活泼，同时避免儿童化；
- 品牌表现是否过强，以至于削弱搜索、关注和资料浏览效率。

## 17. 评审标准

评审每个变体时，按以下问题判断：

1. 第一眼是否明确是面向熊猫爱好者的网站？
2. 是否比现有“档案馆”方向更美观、活泼？
3. 是否仍然显得可靠，而不是廉价或儿童化？
4. 是否能在十秒内找到一只熊猫或开始搜索？
5. 关注关系是否有明确价值？
6. 是否能自然地继续认识相关熊猫？
7. 图片是否承担了足够的情绪和品牌作用？
8. 信息是否仍然清楚、可访问、移动端可用？
9. 哪些模块应从其他变体组合进最终方案？
10. 哪些部分看起来像普通媒体、社交或地图产品，需要去除？

## 18. 原型运行

在 `apps/web` 下运行：

```bash
npm run dev
```

访问：

- `/zh/prototype/panda-fans?variant=A`
- `/zh/prototype/panda-fans?variant=B`
- `/zh/prototype/panda-fans?variant=C`
- `/zh/prototype/panda-fans?variant=D`

底部原型切换器支持按钮和键盘左右方向键。原型只用于方向评审，不应直接提升为生产代码。

## 19. 方向确认后的落地顺序

1. 记录获胜变体及组合原则；
2. 将正式设计政策从“温暖自然史档案馆”更新为确认后的爱好者方向；
3. 更新品牌与公开文案合同；
4. 更新跨 Surface 设计语言；
5. 建立正式 Token、摄影和内容模块规范；
6. 先重做首页和熊猫资料首屏；
7. 再重做关注动态、家族和地点探索；
8. 最后调整来源、资料状态和方法区域的层级；
9. 通过移动端、无障碍、性能和真实数据进行验收；
10. 删除原型变体和切换器，仅保留原型分支与决策记录作为依据。
